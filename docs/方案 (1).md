## 二、模块规格

### S1 采集服务化

- **现状**：`backend/app/connectors/` 已有 hotlist / rss / govdoc / websearch 四个采集器，
  统一输出 `SourceItem`，去重三件套（`content_fingerprint` / `canonical_url` /
  `independence_group`）已在 connector 层填充；hotlist 兼容 TrendRadar 结构。
- **要做**：
  1. 统一入口 `collect(kind, params, limit) -> list[SourceItem]`，四源挂同一签名
  2. 单源失效隔离：某源异常只标 `degraded` 并记原因，不拖垮整轮、不静默
  3. 每源超时（默认 10s）与限速
  4. 采集计数写入 S9
- **交付**：`connectors/__init__.py` 暴露 `collect()`；保留调试端点
  `POST /api/collect/preview`（不入库），供现有素材页沿用。
- **验收**：断网时 `collect()` 返回空列表 + degraded 原因，不抛异常；
  单个源超时不影响其余源返回。

### S2 全局舆情流 `feed_items`

- **为什么要独立一张表**：现有采集结果挂在「任务 / 素材」下，没有全局、与任务解耦的
  舆情流 —— 这是「打开就有数据」的前提。绝不能塞进 `Task` 模型。
- **字段**：`id`, `dedup_key`, `title`, `url`, `canonical_url`, `content_fingerprint`,
  `independence_group`, `platform`, `category`, `published_at`, `collected_at`,
  `summary`, `hot_score`, `sentiment`, `sentiment_score`, `sentiment_source`,
  `region_code`, `region_city`, `region_source`, `raw_meta`(JSON)
- **去重**：`dedup_key` = URL 规范化 + 标题指纹；同源转载按 `independence_group` 归并，
  统计时算一条。
- **保留期**：默认 90 天，超期由 `maintenance.py` 的清理任务处理（可配）。
- **验收**：连续采集两轮，第二轮零新增（全被去重命中）；同稿 5 站转载只计 1 条。

### S3 行政区划与地域识别

- **现状**：`backend/app/data/regions.json`（省 / 市两级，54 KB）、
  `connectors/regions.py` 已有识别函数。
- **要做**：
  1. 补齐 `region_source` 枚举：`issuer` / `title` / `body` / `account` / `unknown` 并落库
  2. 识别不出一律 `unknown`，**不进统计**（不许猜）
  3. LLM 兜底必须输出「码值 + 理由」，否则判 `unknown`
  4. 补省中心点坐标表（地图打点、地理布局共用）
- **验收**：10 份政策样本按发布机关识别 ≥90%；未识别的全部 `unknown` 且不参与份额计算。

### S4 情感标注

- **策略**：本地词典 / 模型打标为主（零成本、秒级）；仅低置信度条目走 LLM 复核，
  BYOK 下烧的是用户自己的 key，必须克制。
- **要求**：结果必须带 `sentiment_source`（`lexicon` / `model` / `llm` / `manual`），便于审计。
- **验收**：100 条样本人工抽 20 条，方向与人工判断一致 ≥70%；每条都能查到标注来源。

### S5 采集调度

- **现状**：`monitoring.py` 已有每分钟 tick 的调度循环（已挂载 maintenance 清理）。
- **要做**：feed 采集挂进**同一循环**（节流，不新开线程），间隔
  `FEED_INTERVAL_MIN`（默认 15）；单进程锁防重入；受 `FEED_ENABLED` 开关控制。
- **验收**：启动后 15 分钟内库中出现采集记录；`FEED_ENABLED=0` 时不采集且不报错。

### S6 变化检测（feed 层）

- **现状**：`research_changes.py` 的 `compare_research_ledgers` 服务于报告版本对比
  （节点增删 / 立场变化 / 关系增删），**不改它**。
- **要做**：新增 `feed_changes.py`，输出四类变化：
  1. 新增 / 消失的关键词簇
  2. 情感转向（同簇负面占比 24h Δ≥15pp）
  3. 跨省扩散（同 `independence_group` 24h 内出现在不同省）
  4. 沉默地区（地域范围内某省占比 <5% 且近 7 天零新增）
- **验收**：构造两条同题不同省条目 → 跨省扩散被检出。

### S7 告警规则引擎 + 通知通道

- **新表**：`alert_rules`（conditions / channels / quiet_hours / daily_cap / enabled）、
  `alert_events`（rule_id / feed_item_id / matched / notified_at / payload）
- **默认规则 7 条**（继承 F5 五条 + F13 两条）：

  | 级别 | 规则 |
  |---|---|
  | P0 | 关键缺口（critical gap）新增 |
  | P1 | 负面强关系新增（strength ≥ 4） |
  | P1 | 叙事份额 24h Δ ≥ 15pp |
  | P1 | 跨省扩散 |
  | P2 | 立场翻转 |
  | P2 | 声量环比 ≥ 3× |
  | P2 | 沉默地区 |

- **去重与节流**：`dedupe_key`（规则 + 条目）6 小时内一次；静默时间窗（默认 22:00–08:00）；
  每日推送上限；发送写审计日志。
- **通道**：邮件复用现有 `email_sender.py`；新建 `backend/app/notifiers/`
  （wecom / feishu / dingtalk 三个 webhook 客户端，各 ≤80 行）；
  配置存 `data/notify_settings.json`（沿用 `llm_settings.json` 惯例）。
- **验收**：构造命中条目 → 落 `alert_events` → 收到测试邮件；6h 内同规则同条目只发一次。

### S8 地图底座

- **现状**：`frontend/public/geo/china.json` 已存在（35 个要素，含台湾、香港、澳门）；
  `report-geo-map.tsx` 已实现省份着色。
- **缺口（红线）**：**当前底图缺南海诸岛（九段线）小窗**，合规要求必须有。
- **要做**：
  1. 从自然资源部标准地图服务（bzdt.ch.mnr.gov.cn）取标准底图与审图号，补齐南海诸岛小窗
  2. 审图号写入 README 与地图角标
  3. 省中心点坐标表（打点 / 地理布局共用）
  4. 交互地图与 Word 静态 PNG 共用同一底图（第二阶段渲染时用）
- **验收**：地图含完整台湾与南海诸岛小窗；角标显示审图号；无数据省份灰显不编数据。

### S9 采集健康与配额

- **新表**：`feed_collect_runs`（source / started_at / finished_at / fetched /
  inserted / deduped / error）
- **后台**：既有 `/admin-console/content` 加「采集任务」区块（这是运营后台，不是报告页）：
  各源今日调用数、插入数、去重数、`degraded` 次数、最近失败原因。
- **验收**：故意配一个坏端点 → 后台显示失败原因，其余源正常。

## 五、合规与红线（继承旧计划第六章）

1. **不抄代码**：第三方只允许「外部进程 + 文件交换」集成；提交说明写明参考了谁的思路。
2. **数据源分级**：L1 热榜 / RSS / 政务公开 / 搜索（默认开，限速 + robots）；
   L2 社媒登录态（外部进程、默认关、仅研究用途）；L3 绕过登录 / 批量个人信息（永不实现）。
3. **地图合规**：同一份标准底图 + 审图号 + 南海诸岛小窗；不自行描边；数据不足灰显并提示。
4. **地域不编造**：识别不出即 `unknown`，不进统计。
5. **BYOK 不破坏**：采集与监测不引入任何服务端密钥；LLM 只用于低置信度复核。
6. **零回归**：`FEED_ENABLED` 默认 on，关掉即回到当前产品形态（路由不注册、调度不启动）；
   每个模块合入前跑后端全量 pytest + `体检.bat`。
7. **单进程部署**（既有红线）：队列认领、限流、订阅均为进程内存态，多进程会分裂。
